# 视觉 Overlay 私有分支维护说明

第三只眼冷却提醒与主版本共用同一套逻辑：以首次开始信号为锚点，默认 300 秒；设置页可在
300 秒（无特殊装备）与 240 秒（特殊装备）之间下拉选择。刷新和结束信号只更新状态，不会
重新起算冷却。

此功能只存在于本地 Git 分支 `visual-overlay-local`，不推送远端，也不写入公开版
`latest.json` 或 GitHub Release。

## 与公开版同步

每次公开版发布并提交到 `main` 后，在本地执行：

```powershell
git switch visual-overlay-local
git merge main
powershell -ExecutionPolicy Bypass -File scripts\build_visual_private.ps1
```

合并时保留视觉分支中的下列专用文件和改动：

- `buffwatcher/music_overlay.py`
- `buffwatcher/overlay_bridge.py`
- `buffwatcher/theme.py`
- `buffwatcher/settings_gui.py` 中的“音乐技能HUD提醒”与“其他技能HUD提醒”设置区
- `run_overlay.py`
- `scripts/build_visual_private.ps1`
- `scripts/deploy_visual_private.ps1`
- `scripts/make_visual_private_config.py`
- `scripts/build_release.ps1` 中的 `IncludeVisualOverlay` / `PrivateBuild` 支持
- `buffwatcher/updater.py` 中私有包独立更新通道与公开源隔离判断

私有构建脚本会读取当前 `latest.json` 的版本号，生成同版本的“视觉Overlay内测版”。本机始终覆盖
投放目录中的固定 `视觉Overlay内测版` 文件夹，ZIP 则按版本保存到统一的 `旧版留存` 目录；
不再为每个版本创建新的解压文件夹，也不会上传文件。

“战斗占星追踪”标签页包含卡牌与冷却 HUD 配置：用户依次选择1—5号牌、每张牌所需计数（5或6），并为
星辉领域、疾旋突袭、星之爆破、空间斩、回旋冲击、重力场、星辉绽放、致命坠击选择当前花色。只有全部
字段填写完整后才启动实时推断；命运之轮按过牌规则立即取得卡组下一张牌。星辉领域和疾旋突袭使用两个
独立冷却追踪开关：双开时在画面中央下方左右对称显示 90 px 可用图标，单开时自动居中。冷却中的技能
不显示；同花色持牌允许无视 CD 时立即显示。星辉领域和疾旋突袭暴击均按每轮成功施放最多一次的规则
将冷却终点减少 2 秒；疾旋突袭单次施放的三段攻击即使多段暴击，也只减少一次。
主循环的事件处理和无事件时间刷新都会传递同一个占星状态机，避免有效快照被随后的定时刷新清空。
占星状态机与 HUD 仅在魔法盾已确认本人、且场上存在已定义关键 Boss 或指定测试木头人时启动；离开场景
立即清空推断，重新进入后从卡组起点重新计算。Overlay 每 0.5 秒重申最新冷却快照，以覆盖可能残留的
上一轮完成点。

作者本机目录的设置采用“保留已有值，只补新增字段”策略。构建前优先读取 Documents 投放目录中
最新视觉内测版的 `程序文件/BuffWatcher/buffwatcher.config.local.json`；找不到时才回退到仓库根目录
的本地配置，再找不到才使用公共默认配置。构建仍会为 ZIP 单独生成公共默认配置，因此作者的开关、
提前秒数、铃声、图标路径、第三只眼 240 秒等个人选择不会进入发给内测人员的默认设置，也不会在
下次本机构建时被覆盖。

覆盖固定运行文件夹前，构建脚本会临时保留并恢复 `logs` 与 `assets/custom`；本地配置则通过
`buffwatcher.config.local.json` 的继承流程写回。因此更新本地运行版不会清空历史诊断日志、
自定义 HUD 图标或作者个人设置。

## 独立自动更新通道

V1.25e 及更早视觉包使用过的 `visual/latest.json` 与 `visual/v2/latest.json` 均已永久停用，
不能重定向或恢复。V1.3 视觉版必须手动安装一次，并改用全新清单：

```text
https://nogi-broadcaster-updates.oss-cn-hangzhou.aliyuncs.com/channels/v13/visual/latest.json
```

视觉包声明 `update_channel=nogi-v13-visual` 和 `strict_update_channel=true`，只接受通道标识一致的
清单与更新包；即使该地址不可用，也不会回退到公开版、GitHub API 或任何旧入口。

视觉更新码仍采用 `公开基础版本码 * 100 + 视觉修订号`。V1.3 的基础码为 `10300`，首个视觉
修订版为 `1030001`。OSS 对象结构为：

```text
channels/v13/visual/latest.json
channels/v13/visual/releases/v1.3/r1/V1.3-visual-r1.zip
```

发布使用 `scripts/deploy_visual_private.ps1`。脚本会先构建并覆盖本机固定视觉运行目录、保存 ZIP
到 `旧版留存`，再计算大小与 SHA-256，先上传不可变 ZIP、执行 `ossutil stat`，最后才替换
`channels/v13/visual/latest.json`。必须同时传入
`-ChannelRoot channels/v13/visual -ManifestObject channels/v13/visual/latest.json`；旧对象结构仍受
`AUTO_UPDATE_DISABLED` 强制锁定。AccessKey 只通过发布进程环境变量传给 ossutil。

旧视觉包不能通过自动更新迁移，因此每名既有内测人员必须手动覆盖安装 V1.3 visual revision 1；
之后只有 V1.3 新通道内的更新可自动完成。当前 OSS 是公共读、路径不公开列举，属于
“不主动公开”的内测分发，并不等同于带身份认证的私有下载。

## 视觉版行为

- 设置窗口改为标签页布局：通用提醒保留在“常规提醒”；湛蓝内伤、布四安全屋、Boss 血量机制、
  布三红球与布 3/4 激光归入“副本机制提醒”；音乐技能 HUD、其他技能 HUD 与独立的
  “可视化DEBUFF提醒”归入“可视化HUD”；爆炎箭归入独立的“短CD技能冷却提示”标签。
  提醒音量与保存按钮位于固定底栏，切换标签时始终可见。
- 使用独立、无焦点、置顶、鼠标穿透的透明窗口；只在洛奇位于前台时显示。
- Toast 宽度 300 px，位于游戏客户区上方中央，多个提醒纵向堆叠。
- “音乐技能HUD提醒”中的活跃曲、战争序曲和行进曲各占一行，可分别启用、设置
  HUD 提前提醒时间和开关铃声；默认 15 秒，铃声均默认关闭，计时与铃声完全独立于语音播报。
- Toast 外层底板透明；图标右侧是与图标等高的粗进度条，条件名和倒计时叠在条内，
  米橙色填充随剩余时间收缩，不显示“自己”等目标副标题。
  大于 2 秒时倒计时只显示整数，最后 2 秒才显示到 0.1 秒。
- 30 ms 刷新；到 0、收到移除包或刷新为新结束时间时，旧 Toast 立即撤销/重建。
- Toast 出现时播放一次提示音；初始寿命不短于 4 秒时，在剩余 3 秒再播放一次提示音。
  每一行的铃声开关可单独关闭这两次铃声，不影响该项 HUD 本身。
- 三项音乐条件都有独立的默认 PNG 与替换入口。选择的 PNG/GIF 会复制到
  `assets/custom/visual_hud`，避免依赖原图片位置；留空时使用后备音符，“恢复默认图标”
  会还原随包提供的对应图标。
- Toast 与设置页共用米色、棕色和橙色主题常量。
- CCID 192（活跃曲）、680（战争序曲）和 193（行进曲）均默认启用。
- 启用对应的徒安静默开关后，若徒安之歌仍在生效、其结束时间晚于即将结束的音乐 Buff，且该音乐 Buff 没有
  `music_toan_extended` 标记，则认为本次续时可覆盖原到期点，立即撤销 HUD。已经被徒安
  延长过一次的版本不会走此抑制，仍正常提醒。音乐语音区的开关名为
  “检测到徒安之歌时，静默播报”，音乐 HUD 区的开关名为“检测到徒安之歌时，屏蔽视觉提醒”；
  两者默认关闭且互相独立。
- “其他技能HUD提醒”总开关默认关闭，内含魔法阵、崩坏波动、马纽斯秘药、净化之浪和
  生命的温度五个独立开关与图标替换入口；无铃声、无提前倒计。只有在布本 1--4 王或凯莱赫的
  实体处于活跃战斗状态时，满足条件的图标才会在屏幕最左侧竖向常驻。
- 魔法阵以本人 `SkillId 10103 / EventId 12 + 140 秒`判断就绪；崩坏波动以本人
  `SkillId 59005 / EventId 12 + 180 秒`判断就绪。两者重新收到 E12 后立即从图标列移除，到新的冷却完成点再显示。
- 马纽斯秘药 `CCId 835` 和净化之浪 `CCId 645` 在本次运行中已经观测到效果结束后显示，
  重新获得对应效果时移除。
- 生命的温度不再使用顶部到期倒计。只有在本次运行中观测到 `CCId 874` 消失后才点亮左侧图标；
  之后即使重新获得 1--4 层也保持显示，只有 `MCSTCT >= 5` 时才移除。该单项开关默认关闭。
- “短CD技能冷却提示”中的爆炎箭和水流箭分别使用本人
  `SkillId 59060 / EventId 12`、`SkillId 59061 / EventId 12` 作为唯一冷却起点；E12 到达时
  立即隐藏对应图标，默认 6 秒、10 秒后在音乐 BUFF 提醒区域下方居中常驻，直到下一次本人 E12。
  每项均有独立开关、冷却时间输入框和 PNG/GIF 图标替换入口；该 HUD 在已定义关键 Boss 战中绘制，
  也可由测试木头人 `RaceId 4860` 单独激活。木头人不会激活其他技能 HUD、DEBUFF HUD、
  Boss 血量提醒或魔法盾漏开提醒。
- 识别到布本 1--4 王或凯莱赫实体后，在游戏客户区约 77% 高度处显示一排尚未达成
  “DEBUFF 上齐”条件的图标。九项条件沿用现有数值门槛和实体状态机；达标时图标消失，
  移除、自然到期或数值不达标时重新出现，图标数量变化后整排自动重新居中。
- 已达标 DEBUFF 进入“破防 DEBUFF 续期提醒”的同一提前秒数后，图标重新出现并以
  1.2 秒周期慢闪；设置页“关键敌人 DEBUFF 提醒”区块底部的
  “可视化DEBUFF到期提醒”可单独关闭慢闪，但不会关闭缺失 DEBUFF 常驻图标。
- DEBUFF HUD 使用随包提供的九张 PNG，不播放任何铃声，也不增加音频设置项。

音乐 Overlay 沿用播报器已经计算好的 `BuffState.end_ms`；DEBUFF HUD 沿用
`KeyEnemyDebuffEntityState` 中的达标状态和结束时间，所以会自动继承徒安延长、Boss
实体切换、数值门槛、移除包和角色过滤。它不读游戏内存，
也不增加 Npcap 之外的运行依赖。

## 服务器时间诊断（本地实验）

视觉内测版恢复为角色登录后启动，并继续通过快速开关魔法盾确认自身角色 ID；不再为了
捕获登录包而预选端口、提前启动抓包组件或改变 WebSocket 握手流程。

游戏暂时没有事件时保持连接，不再每 20 秒主动断开 WebSocket，也不再因连续空闲而重启
Mabicat。只有 Mabicat 进程真实退出或 WebSocket 明确报错才进入恢复；恢复后保留已确认的
角色 ID。启动后暂未出现 `LISTEN_PORT` 时继续等待并显示“等待游戏数据”，不主动杀进程，也不要求玩家移动或操作技能。魔法盾仅用于连接成功后的单次角色 ID 确认，不是在线状态检查或周期性心跳。

角色内收到 `0x659C` 时，会把实体字段、服务器时间、本机收到时间、换算后的墙上时间、
本机与服务器偏差以及魔法盾已确认的自身 ID（若当时已确认）追加到本地服务器时间诊断
NDJSON。记录中的 `Applied` 固定为 `false`；本地配置使用 `shadow` 模式，因此该时间不参与
音乐 Buff、语音播报或 HUD 倒计时。
